## 확정한 범위

사용자는 이번 구현에 **공개 과제 공간과 로그인하는 개인 계정 영역을 함께 포함**하기로 했다. 이메일 가입과 카카오·네이버·구글 소셜 로그인을 모두 선택했다. 웹은 Spring Session JDBC·Secure/HttpOnly 쿠키·CSRF 검사를 채택했다. Android 인증 인계 계약은 별도다.

- 공개 과제 공간: 기존 44개 T06 조건과 번호 없는 필수 조건을 그대로 적용한다. 로그인 없이 계획·할 일·실행·돌아보기·다음 계획·내보내기를 모두 제공한다. 제출 주소의 첫 화면에 지정 공개 문구를 그대로 표시하고, 이 안내가 공개 과제 공간에 대한 것임을 구분한다.
- 개인 계정 영역: 현재는 본인만 조회·수정한다. 공개 과제 자료와 개인 자료를 분리한다. 향후 공동 편집을 고려해 설계하지만 지금 공유·초대·공동 편집을 활성화하지 않는다.
- 일정: 기존 8~10시간은 공개 웹 과제의 계획이다. 이번에 추가한 인증·개인 영역·접근 분리 검증까지 그 시간에 포함된 것으로 간주하지 않는다. 추가 시간은 외부 연결·배포 검증을 반영해 산정한다. Android 일정도 별도다.

## 설계에 적용할 경계

다음은 서버/DB 구현에 적용한 경계다. 실제로 확인한 범위와 아직 실행하지 않은 검사는 backend-verification.md에 분리해 기록한다.

- 서버가 공개/개인 자료 범위와 인증된 주체의 접근 권한을 결정한다. 요청에 포함된 계정 ID만으로 접근을 허용하지 않는다.
- 목록·검색·상세·수정 이력·완료/되돌리기·실행·돌아보기·근거·다음 계획 연결·내보내기 모두 같은 접근 범위를 적용한다. 공개 API나 다른 레코드 ID를 통한 개인 자료 접근을 허용하지 않는다.
- 내보내기의 ‘전체’는 접근이 허용된 해당 공간의 도메인 자료 전체다. 공개 내보내기에 개인 기록·계정 정보·인증 정보가 들어가면 안 된다. 개인 내보내기도 다른 계정의 자료를 포함하지 않는다.
- 요청 키의 응답 재사용 전에 권한을 확인한다. 공개 공간 또는 다른 계정에서 같은 요청 키를 보내도 개인 응답이 노출되지 않게 요청 범위를 구분한다.
- 서로 다른 공간이나 권한 없는 계획·할 일·회고 사이의 관계 생성을 거부한다. SSR과 브라우저·Android 호출 모두 동일한 서버 접근 검사를 거친다.
- 기존 아홉 도메인 표에 workspace_id와 공간별 FK·요청 키 범위를 추가하고 계정·식별자·이메일 자격·토큰·세션·메일 큐·알림 설정을 V1~V3 migration으로 구현했다. 실제 21개 표의 관측은 백엔드 계약에 기록한다. 최종 배포 검증은 별도다.

## 클라우드 우선과 채택한 구성

2026-09-08 후속 결정: 사용자가 JDBC·Spring Security·웹 JDBC 세션·외부 SMTP와 휴지통 복원(REC-01)·계획 틀 복제(REC-02)·선택형 알림(REC-03)을 모두 채택했다. n8n은 후속 알림·운영 자동화로 검토하고 인증 메일은 Spring에서 외부 SMTP로 전송한다. 클라우드부터 구현하고 WTR Pro로 이전할 수 있도록 준비한다.

WTR Pro는 Ryzen 7 5825U·RAM 32GB·6TB×2·2TB×1이며 CCTV용 하드로 24시간 사용 가능하다는 사용자 진술이다. 초기 이용자는 약 10명 예상이다. 실제 가용성·OS·외부 접속·월 예산은 미확인이다. 초기 운영은 클라우드, WTR Pro는 후속 이전 대상이다.

메일 설정 예시는 Brevo SMTP(smtp-relay.brevo.com:587, STARTTLS) 기준으로 준비한다. SMTP 로그인과 SMTP 키는 환경 변수로 주입한다. 발신 도메인 인증(Brevo code·DKIM·DMARC), 트랜잭션 발송 활성화, Gmail·네이버 실제 수신 확인은 남아 있다. 외부 서비스를 써도 받은편지함 도착을 보장하지 않으며, WTR 이전 후에도 같은 외부 SMTP를 유지한다.

Java 21.0.12.1과 Spring Boot 4.1.1·Gradle 9.7.1 컴파일을 확인했다. JDK 소켓 전용 임시 경로를 지정하여 로컬 빌드 오류를 해결했다. 사용자가 알려 준 MariaDB 포트는 3919이고 127.0.0.1:3919 초기 응답에서 12.3.3을 확인했다. 기존 DB 로그인·데이터 변경은 하지 않았다. 상세 실행 증거는 후속 검증 기록에 남긴다.

## 무료 호스팅·메일 준비·프론트 API 후속 지시

2026-09-08 최신 결정: 사용자가 최종 클라우드 제공자로 Vultr를 선택했다. 사용자는 작은 클라우드 서버로 줄일 필요가 없고 한 달 안에 이전할 것으로 예상한다고 밝혔다. WTR Pro로의 이전을 목표로 서울(icn) Shared CPU AMD High Performance 8vCPU·RAM 16GB·350GB 한 대를 체험용으로 추천하며 공식 카탈로그의 서버 요금은 월 US$96이다. US$250·최대 30일 프로모션의 실제 적용/만료는 확인 전이다. 새 한국 서버의 DB·백엔드·Caddy 배포와 SMTP 시험을 확인했다. 공개 HTTPS·API·Swagger는 확인했고 프론트는 미구현이다. Brevo 도메인 Authenticated는 사용자 진술로 확인했다. 발신자 PlanDoSee <no-reply@plandosee.app>의 서버 SMTP 시험을 통과했고, 사용자가 네이버 받은편지함 도착을 확인했다. 소셜 제공자 앱 등록·키·콜백·검수는 프론트 완성 뒤 한 번에 진행한다. 클라우드부터 운영하고 WTR Pro로 후속 이전하는 방침을 유지한다. 구상 저장소의 OpenAPI 0.2.0·Swagger UI·프론트 안내는 42개 경로·59개 작업·38개 모델·예시 43개와 소스 대조/브라우저 검사를 통과했다.
