## 화면·기술 제안

- 기존 공개 `/`, `/plans`, `/plans/[planId]`, `/tasks/[taskId]`, `/review` 흐름을 유지하고 전체 할 일 `/tasks`와 휴지통 `/trash`를 더한다.
- 개인 화면은 `/account` 아래에 같은 기능 컴포넌트를 재사용한다. auth와 private 라우트 그룹을 분리해 로그인·메일 확인·재설정 화면에 로그인 장벽을 붙이지 않는다.
- Next.js App Router SSR·React·TypeScript, CSS Modules·CSS 변수, 기본 HTML 폼·React 상태·내장 fetch를 제안한다. 구체적인 패키지 버전은 설치 전에 공식 정보를 확인해 잠근다.
- 브라우저는 같은 출처 API를, SSR은 `API_INTERNAL_URL`의 Spring을 조회한다. 업무 데이터 no-store, 요청자 세션 전달, 브라우저 CSRF 발급, 공개/개인 분리와 로그아웃/계정 전환 상태 해제를 적용한다.
- 같은 요청 의도에는 같은 Idempotency-Key·본문, 새 의도에는 새 키를 사용한다. 실행 저장 후 완료는 `{cycle, execution}` 한 번의 원자 요청이다. 완료 사건 응답 후 상태를 재조회한다.
- Review 숫자·조건·근거는 한 응답으로 표시한다. 날짜·시간·집계·접근 권한은 기존 서버 계약을 유지한다. 원문 44개·번호 없는 조건·AUTH/REC·DB/OpenAPI 필드를 변경하지 않는다.

## 이번 작업에서 확인한 것

- RULES의 원문 44개 `id/text/verify`가 변경되지 않았고 전부 구현 단계·화면·검증 그룹에 연결됐다.
- 번호 없는 조건 18개와 AUTH-01~07·REC-01~03의 추가 검증 항목을 연결했다. 검증 증거 7개 범주도 V01~V10에 포함한다.
- 백엔드와 설계 저장소의 OpenAPI·DB 계약은 SHA-256이 일치한다. OpenAPI는 42개 경로·59개 작업·38개 모델이다.
- 앱 생성·패키지 설치·build·브라우저 테스트·서버 재점검·DB 변경·메일 발송·배포·사용자 실제 기록 생성은 실행하지 않았다. 문서 구조 확인을 앱 검증으로 세지 않는다.

노션 연결·재조회 결과와 최종 문서 검사 결과는 `docs/notion-publication.json`의 `frontend_implementation_plan`과 Nextjs의 `docs/planning-verification.json`에 기록한다. 다음 구현 단위는 공개 홈→계획 SSR→생성 폼→CSRF/쿠키→저장 후 재조회인 F0다.
