- 2026-09-17 최신 사용자 확정: 펼친 할 일 헤더의 우선순위 배지 테두리를 제거하고 기존 단계별 배경색과 문구는 유지한다.
- 2026-09-18 최신 사용자 확정: 작업 탭과 펼친 할 일 실행 패널의 확인 대기 상태 모두에 `시간 수정 / 기록 확인`을 표시하고 기록 확인 전환 모션을 추가한다. 진행 작업바의 내부 여백·상태점·시간·행동 버튼을 축소하며 확인 대기 작업 탭의 초록 보조 문구는 8px로 줄인다.
- 2026-09-18 사용자 최종 승인: 현재 전체 메인 화면의 정보 구조, 할 일 컴포넌트, 작업탭, 상단 작업바와 인터랙션·모션을 확정한다. 이후 변경은 새 후속 지시로 관리한다.
- 2026-09-18 사용자 확정 작업 순서: [전체 화면 시안 제작 계획](../../PDC_Diary_Nextjs/docs/redesign/frontend-screen-production-plan-2026-09-18.md)의 모든 화면을 개별 시안 파일로 먼저 만들고 승인받은 뒤 백엔드 계약 확정과 제품 구현을 시작한다.
- `작업탭`은 할 일 안쪽 실행 패널, `작업바`는 상단 전역 상태 줄로 부른다. 작업바의 기록 확인은 `기록됨` 버튼 피드백과 성공 문구·초록 강조를 먼저 보여 준 다음 축소·퇴장시키며, 작업탭의 기록 확인도 연결된 작업바에 같은 모션을 재생한다.

기준일: 2026-09-17  
상태: 상세 UI 설계·인터랙티브 시안 완료 · 메인 화면 사용자 승인 완료 · 제품 구현 미착수

이 문서는 2026-09-17 이후 프론트 설계의 최신 기준이다. 2026-09-11까지의 화면과 주소는 당시 구현 기록으로 보존하지만 새 화면은 그 구조나 주소와 호환될 필요가 없다. 기존 데이터는 보존하고 새 화면에서 복원한다.

## 사용자 확정

- `Plan`은 소프트웨어 개발·과제·이력서 제출 등 목적을 가진 **스프린트**로 이해한다. 스프린트 기간은 자유롭게 정하되 1주·2주·4주 빠른 선택을 제공한다.
- 유효한 로그인 세션 쿠키가 있으면 랜딩을 거치지 않고 개인 대시보드로 간다. 로그인하지 않은 사용자는 랜딩에서 공개 영역과 개인 영역을 명확히 구분한다.
- 로그인 없이 사용하는 공개 영역의 최종 제품 이름은 **체험실**이다. 로그인한 사용자의 개인 영역은 **내 작업실**로 표시한다.
- 개인 대시보드는 `오늘 할 일 → 스프린트 보드 → 전체 일정` 순서다. 통계와 회고는 별도 화면으로 두되 어느 업무 화면에서도 쉽게 갈 수 있어야 한다.
- 가장 빈번한 행동은 일정 한눈에 보기와 할 일 생성·조회·수정·삭제이다. 할 일 마감일과 스프린트 우선순위를 강하게 드러낸다.
- 오늘 요약은 `오늘 마감·지연`과 `완료·막힌 할 일` 두 묶음으로 보여 준다.
- 반복 일정은 제공하며 수정은 전체 반복 일정에 한꺼번에 적용한다. 개별 발생분 수정은 이번 범위에 넣지 않는다.
- 기존 `현재 시각 남기기` 한 번 누르기 방식은 폐기한다. 할 일에서 기본 `1시간 작업 시작`을 누르면 서버가 작업 세션을 만들고, 모든 로그인 업무 화면의 본문 최상단에 얇은 작업 탭을 쌓아 할 일 이름·분 단위 진행 시간·자동 종료 시각·`중단`·`+30분 연장`을 보여 준다. 최상단에는 이 축약 탭만 두고 펼친 상세는 목록 자리에 남긴다. 작업 탭은 닫을 수 없고 본문을 덮지 않는다. 중단 또는 자동 종료 후에는 계산 시간을 확인·수정한 뒤 실행 기록으로 확정한다.
- 2026-09-17 최신 사용자 교정: 별도 단독 컴포넌트에서 비슷하게 재구성하는 방식도 폐기한다. 롤백된 전체 16:9 원본 시안을 작업 기준으로 고정하고, 그 안의 기존 낮은 접힌 할 일 행을 실제 마크업·열 너비·타이포 그대로 유지한 채 할 일 컴포넌트 내부만 수정한다. 펼쳐도 머리 행을 다른 구조로 교체하지 않으며 기존 높이·상태·마감 배치와 모션을 유지한다. 본문은 최대 3줄까지만 접어 보이며 실제 렌더 결과가 3줄을 넘을 때만 중앙 화살표를 표시한다. 우선순위는 헤더의 마감 왼쪽에서 접힘 해시태그·펼침 색상 배지로 전환하고, 대표 긴 본문은 첫 문장 뒤에서 다음 줄을 시작한다. 전체 스프린트의 마감 순환 버튼은 목록 도구 줄의 필터 바로 왼쪽에 같은 높이로 둔다.
- 할 일은 마우스 또는 터치로 바로 재배치한다. 별도 순서 변경 모드와 키보드 순서 변경은 제공하지 않는다.
- 모든 클릭 가능한 요소에는 눌림·호버·포커스·대기·성공·실패 피드백을 둔다. 모션은 iOS처럼 부드럽게 느껴질 정도로 짧고 일관되게 쓰며, `prefers-reduced-motion`에서는 줄인다.
- Jira처럼 정보 밀도와 스프린트 흐름은 명확하게 하되 진한 녹색은 강조 글자 등 소량에만 쓴다. 기존 글꼴은 유지하고 아이콘은 정렬된 SVG를 사용한다. 정보성과 감성의 균형을 유지한다.
- 모든 화면의 의미 색상은 [UI 명세의 공통 색상쌍](../../PDC_Diary_Nextjs/docs/redesign/frontend-redesign-ui-spec-2026-09-17.md#공통-의미-색상쌍)을 공유한다. 채워진 초록 핵심 행동은 라이트 `#246B55`, 다크 `#2D715A` 배경과 흰 글자·흰 아이콘만 사용하며, 연한 성공 상태면은 별도의 진한/밝은 초록 전경 조합을 사용한다.
- 날짜·기간·우선순위·상태처럼 유효한 값이 정해진 항목은 직접 입력시키지 않고 알맞은 선택기를 제공한다. 텍스트 입력은 이름·설명·회고처럼 자유 입력이 반드시 필요한 값에만 사용한다.
- 첫 사용에는 중요한 상호작용마다 코치마크를 보여 준다. 코치마크 완료 여부와 버전을 계정에 저장하고 큰 개편으로 버전이 바뀌면 전체 안내를 다시 보여 준다.
- 기본 키보드 접근은 Tab·Enter·Space·Escape와 분명한 초점 표시까지 제공한다. 키보드만으로 순서를 바꾸는 흐름은 만들지 않는다.
- Chromium 계열 브라우저를 기준으로 하고 최소 화면 폭은 iPhone mini 수준인 320px로 검증한다. 데스크톱과 모바일을 동시에 설계한다.
- 삭제는 확인창을 거친다. 상태 변경은 즉시 조용히 반영한다. 이동은 즉시 수행하고 되돌리기를 제공한다. 중요한 결과와 오류는 상단 알림 영역으로 알린다.
- 기존 주소 호환은 인수 기준이 아니다. 새 정보 구조에 맞게 경로를 다시 정할 수 있다.
- 푸시는 운영 배포 승인 전에도 가능하다. NAS 운영 배포는 최종 디자인 승인과 사용자의 배포 승인을 받은 뒤 수행한다.

## 제품 구조

### 로그인 사용자

1. **개인 대시보드**
   - 오늘 할 일 두 묶음
   - 넓은 할 일 검색과 본문 `할 일 추가`
   - 현재 스프린트 보드와 위험 요약
   - 주간·월간 일정
   - 최근 작업과 빠른 이어 하기
2. **통계**
   - 완료·지연·막힘·예상/실제 시간과 차이
   - 각 숫자에서 같은 응답의 근거로 이동
   - 주간 사실 요약
   - 2026-09-18 초안은 기간·스프린트 범위가 모든 수치와 근거에 함께 적용되고, 선택한 수치의 근거를 같은 화면 아래에서 모션으로 전환하는 배치를 사용한다. 캘린더는 사용자 승인 완료, 통계는 사용자 검토 중이다.
   - 사용자 화면에는 내부 계약 용어인 `근거`를 그대로 노출하지 않고 `완료한 일 / 지연된 일 / 막힌 일 / 예상 시간 항목 / 실제 작업 기록 / 시간 차이 내역`으로 표시한다. 주간 사실 요약은 두 줄로 제한하고 핵심 수치·선택 항목 헤더의 장식 아이콘은 사용하지 않는다.
   - 할 일 예상 작업시간은 선택 입력이다. 예상 대비 비교는 예상시간이 있는 같은 할 일 집합만 사용하고 예상 입력·미입력 수를 함께 밝힌다. 미입력 할 일의 확정 실행 기록은 전체 실제 기록에서 유지한다.
3. **회고**
   - 근거를 보면서 고칠 점 작성
   - 다음 스프린트 생성과 출처 연결
   - 다음 스프린트 기간은 시작일·종료일을 고르는 달력형 날짜 범위 선택기, 우선순위는 현재 값 하나를 보여 주고 `높음 / 보통 / 낮음` 목록을 펼치는 단일 선택기로 입력한다. 날짜 범위는 종료일을 고른 뒤에도 달력을 유지해 범위를 확인하게 하고 `선택 완료`에서 닫는다. 기간과 우선순위를 일반 텍스트 입력기로 받지 않는다.
   - 완료한 플로우 카드는 반투명 흰색 오버레이와 `완료` 표시로 낮춘다. `지금 만들기`는 결정 카드 아래에 별도 생성 카드를 열고 스프린트 이름에 자동 포커스하며, `돌아가기`는 생성 카드를 닫고 고칠 점 입력으로 복귀한다. 마지막 결정 카드와 생성 카드의 외곽선은 다른 플로우 카드와 같은 중립 경계·모서리·그림자로 통일한다.
4. **설정**
   - 계정 동기화 환경설정과 코치마크 다시 보기
   - 알림·휴지통·내보내기 등 보조 기능

### 로그인하지 않은 사용자

- 랜딩에서 서비스 소개, 개인 일정 정리의 장점, 로그인 행동을 먼저 보여 준다.
- 기존 무인증 필수 기능은 개인 정보와 섞이지 않는 별도 **체험실**에서 유지한다.
- 체험실 진입 시 `체험실의 내용은 누구나 볼 수 있어요. 개인 일정은 로그인 후 내 작업실에서 관리해 주세요.`라는 토스트를 한 번 보여 준다.
- 공개 안내 원문과 익명 변경 가능성은 필수 RULE대로 유지한다.

## 캘린더 범위

캘린더는 유지하되 과도하지 않게 줄인다. 반복 일정과 여러 마감일을 한눈에 보는 요구에는 달력 형태가 유용하지만, 별도 일간 달력은 오늘 할 일과 겹친다.

- 첫 범위: 월간·주간 보기, 마감일과 반복 발생분, 날짜 선택 시 해당 할 일 목록.
- 주간 보기에서는 일정 카드를 날짜 열 사이로 드래그해 마감일을 변경한다. 드래그 원본·대상 열·착지 카드에 연속 모션을 적용하고, 성공 시 선택 날짜·날짜 목록·월간 표시와 저장 자료를 함께 갱신한다.
- 제외: 별도 일간 캘린더, 복잡한 자원 배정, 외부 캘린더 양방향 동기화.
- 오늘은 대시보드의 오늘 할 일이 담당한다.

이 축소 범위는 AI 추천을 사용자가 확정했다.

## 스프린트 대시보드·계획 선택·실행 기록

- `전체 스프린트`에서는 진행 중인 계획 행 대신 모든 스프린트의 할 일을 한 목록으로 보여 주고 각 할 일에 소속 계획을 표시한다. 개별 계획을 누르면 같은 행 구조를 유지한 채 해당 계획의 할 일만 남긴다.
- 왼쪽 사이드바는 `전체 스프린트`와 개별 계획을 바로 고르는 계획 선택기다. 개별 계획을 고르면 가운데 할 일 목록, 오른쪽 달력·오늘/지연, 검색이 모두 같은 계획 범위로 바뀐다.
- 선택 계획의 할 일은 롤백된 전체 16:9 원본 화면 안에서만 검토한다. 직전 전체 교체안과 별도 단독 재구성안은 사용자 거절로 폐기하며 확정안으로 취급하지 않는다. 기존의 낮은 접힌 행을 그대로 보존하고, 행 자체를 다시 그리지 않은 채 높이·불투명도·화살표 회전으로 상세를 연다. 본문이 실제로 3줄을 넘을 때만 중앙 화살표를 제공하고 `1시간 작업 시작`을 1차 행동으로 둔다.
- `예정 / 진행 중 / 완료` 상태와 막힘 배지는 유지하되, 기본 화면은 3열 칸반보다 확장형 목록을 사용한다.
- `1시간 작업 시작`은 서버에 활성 작업 세션을 만들고 페이지를 닫아도 복원한다. `중단`은 서버 현재 시각으로 경과 시간을 계산하고 `+30분 연장`은 자동 종료 시각을 늦춘다.
- 상단에는 활성 작업의 축약 탭만 작업별 한 줄로 세로 적층하고 제목을 말줄임한다. 펼친 할 일 상세는 목록의 원래 자리에 둔다. 모바일에서는 자동 종료 보조 문구를 줄이고 핵심 시간·중단·연장을 유지한다.
- 자동 종료·중단 결과는 확인 전 임시 상태다. 사용자가 확인하거나 시간을 수정한 뒤 기존 실행 기록의 시작·종료·실제 분으로 확정한다.
- 서로 다른 할 일의 활성 세션은 동시에 허용하고 같은 할 일의 중복 활성 세션만 막는다. 확인 전 통계 제외와 확정 실행만 회고 근거로 사용하는 방식은 AI 추천이며 서버·DB 계약 확정 단계에서 최종 채택한다. 상세: [작업 시간 세션 설계](work-session-design-2026-09-17.md).

## 상태와 저장 위치

### 계정에 저장하고 다른 기기에서도 복원

- 라이트·다크 모드
- 코치마크 완료 여부와 버전
- 기본 대시보드 보기
- 기본 캘린더 보기
- 기본 정렬·그룹 방식
- 사용자가 고정한 필터나 저장된 보기
- 사이드바 접힘 상태

계정 환경설정은 Spring과 MariaDB가 기준이다. 로그인 직후 서버 값을 불러오고 변경 즉시 조용히 저장한다. 충돌 시 최신 서버 값을 적용하고 상단 알림으로 알린다.

### 현재 브라우저 세션에서 유지

- 선택한 스프린트
- 검색어·필터·정렬·그룹
- 오늘/주간/월간 캘린더 위치
- 선택한 날짜와 할 일
- 펼친 카드·상세 패널
- 목록 스크롤 위치
- 통계에서 선택한 근거
- 회고 작성 단계
- 페이지를 오갈 때 작성 중인 입력

`순서 변경 모드`는 기능을 제거했으므로 저장 대상에서도 제외한다. 구조적 화면 상태는 공간·계정별 `sessionStorage`에 보관할 수 있다. 작성 중 입력은 앱 메모리에서만 보관하여 페이지 이동에는 유지하지만 새로고침에는 남기지 않는다. 로그아웃·세션 만료·공개/개인 전환 때 개인 상태를 폐기한다.

### 새로고침하면 폐기

- 저장하지 않은 폼 입력
- 드래그 중간 상태
- 처리 중이던 시각적 애니메이션 상태

서버에 저장한 데이터와 서버가 접수한 요청 상태는 화면의 임시 상태와 구분한다. 응답이 불확실하면 자동 중복 전송하지 않고 서버 기록을 다시 확인한다.

## 채택된 추가 기능

- 계획 안에서 바로 쓰는 `할 일 추가`
- 분류 전 항목을 모으는 Inbox
- 마감·진행·막힘을 이용한 스프린트 위험 요약
- 저장된 보기와 고정 필터
- 주간 사실 요약
- 최근 작업과 빠른 이어 하기

이 기능들은 사용자 채택 사항이다. 세부 계산식과 API 계약은 구현 전에 확정하고 추적표에 연결한다.

## 상호작용 원칙

- 큰 화면 교체 대신 필요한 영역만 갱신하고 입력·초점·스크롤을 유지한다.
- URL은 공유할 가치가 있는 선택과 보기에는 사용하고, 카드 펼침·호버·애니메이션 중간값에는 사용하지 않는다.
- 저장 성공 전에는 확정된 것처럼 보이지 않게 한다. 낙관적 반영을 쓰면 실패 시 원상 복구와 이유를 제공한다.
- 빠른 전환에서는 이전 응답이 현재 선택을 덮지 않게 한다.
- 버튼과 아이콘은 동일한 정렬·터치 영역·상태 모션 규칙을 사용한다.
- 성공은 조용히, 오류·충돌·세션 만료·되돌리기 기회는 상단 알림으로 알린다.

## 코치마크

- 계정별로 `coachmark_version`과 완료 시각을 저장한다.
- 현재 제품 안내 버전보다 저장 버전이 낮으면 주요 흐름 전체를 다시 보여 준다.
- 설명 대상: 할 일 추가, 화면 전체 계획 범위, 오늘 두 묶음, 스프린트 보드, 드래그 재배치, 1시간 작업 시작과 상단 작업 탭 묶음, 캘린더 전환, 통계 근거, 회고→다음 스프린트.
- 코치마크는 건너뛰기·이전·다음·완료를 제공하고 배경만으로 정보를 전달하지 않는다.

## 서버·계약 영향

다음 항목은 현재 화면만 바꾸어서는 완성되지 않으며 Spring·DB·OpenAPI·스키마 계약을 함께 바꿔야 한다.

- 계정별 UI 환경설정과 코치마크 버전
- 반복 일정 틀과 발생분
- 작업 세션의 시작·자동 종료·중단·연장·확인·수정과 활성 세션 복원
- 할 일 예상시간 nullable 전환, null 정렬·내보내기·복원, 전체 실제 합계와 비교용 실제 합계 분리
- Inbox 또는 미분류 할 일의 도메인 규칙
- 스프린트 상태와 위험 요약 계산
- 저장된 보기와 고정 필터

기존 기록 ID·이력·접근 경계·집계 근거·완료 중복 방지·soft delete·전체 내보내기는 보존한다. 기존 주소는 깨뜨릴 수 있지만 저장된 자료는 마이그레이션 또는 호환 읽기로 복원해야 한다.

## 남은 결정

- Spring·MariaDB 계약에서 서로 다른 할 일의 다중 활성 세션과 같은 할 일의 중복 방지를 원자적으로 구현하는 방식을 확정해야 한다. 화면 시안은 축약 작업 탭만 최상단에 쌓도록 만들었다.
- 공개 영역은 `체험실`, 개인 영역은 `내 작업실`로 사용자가 최종 확정했다.

## 현재 확인 범위

- 확인함: 중앙 RULES, 로컬 프론트 설계/진행 문서, 기존 실행 기록 DB 계약, 사용자가 제공한 확정 답변. 주간·월간 캘린더, 계획별 상태와 막힘 배지, `체험실 / 내 작업실` 명칭, 본문 3줄 미리보기와 1시간 작업 세션·상단 작업 탭 묶음을 최신 방향으로 사용한다. 서로 다른 할 일의 다중 활성 작업 허용과 같은 할 일 중복 방지는 사용자 확정이며 구현 계약에서 기술 방식을 정한다.
- 변경함: [상세 UI 설계](../../PDC_Diary_Nextjs/docs/redesign/frontend-redesign-ui-spec-2026-09-17.md), [기계 판독 UI 계약](../../PDC_Diary_Nextjs/docs/redesign/frontend-redesign-ui-contract.json), 대화에서 확인할 인터랙티브 시안을 작성했다. 제품 코드·DB·API·운영 환경은 변경하지 않음.
- 실제 확인: 기존 전체 화면 독립 시안에서 계획 전환·단일 할 일 아코디언·달력 날짜 선택·정렬을 확인했다. 이번 상세 컴포넌트 시안에서는 본문 3줄 미리보기와 부드러운 펼침, 최상단 작업 탭 2개의 세로 적층, 목록 자리에 남는 상세 카드, 30분 연장, 중단 후 확인 대기 상태를 브라우저에서 확인했다. 시안은 서버 연결이 없는 합성 상태이며 제품 구현·320px 최신 시안 재검증·실제 API/DB 연결은 아직 수행하지 않았다.
- 미실행: 제품 구현, Next.js 빌드, 실제 API/DB 연결, 계정 설정 저장, 반복 일정 저장, 커밋, 푸시, NAS 배포.
## 2026-09-17 · 필터 모션과 실행 패널 상태 확정

- 마감 필터는 결과 목록을 순간 교체하지 않고 짧게 아래로 퇴장한 뒤 새 목록이 위에서 제자리로 들어오는 전환을 사용한다. 상단 활성 작업바는 부분 갱신 대상에서 제외한다.
- 접힌 진행 상태는 완료=초록, 진행 중=주황, 예정=중립색으로 구분하되 동일한 48px 박스와 중앙 정렬을 유지한다.
- 펼친 실행 패널의 활성 상태는 `진행중`, 초록 계열 배경, `00:00:00` 실시간 경과 시간, `중단`·`30분 연장` 버튼을 사용한다.
- `1시간 작업 시작`은 세션 생성과 함께 할 일 상태를 `진행 중`으로 즉시 전환한다.
## 2026-09-17 · 상태 선택·작업 시작 전환·마감 단계색 보정

- 진행 상태 선택 버튼의 방향 아이콘을 제거하고 접힘·펼침 모두 예정=중립, 진행 중=주황, 완료=초록의 같은 색을 사용한다.
- 작업 시작 전·진행 중·확인 대기 상세 실행 패널의 외곽 높이는 같은 고정값을 사용하고 시간 글자 크기와 행동 영역 높이도 유지한다. 새 작업 탭은 높이·이동·불투명도가 연속적으로 바뀌며 나타나고 새 상세 패널만 진입 모션을 재생한다.
- `중단` 문구를 850 굵기로 한 단계 강화한다.
- 마감은 오늘=빨강, 내일·이번 주=주황, 이후=파랑, 완료된 할 일=초록의 단계색을 헤더와 하단 태그에 함께 적용한다. 구체 색조는 이번 시안의 AI 선택이며 사용자 후속 지시로 조정할 수 있다.
- 기본 스크롤 동작은 유지하면서 얇은 테마 대응 스크롤바와 자연스러운 hover 강조를 적용한다.
