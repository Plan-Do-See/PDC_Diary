# 01 · 목표·범위·요구사항

[Notion 문서](https://app.notion.com/p/3d60def9f6268101b946cf1927220b29?pvs=204)

<mention-page url="https://app.notion.com/p/3d60def9f62681c2bca2cf1e7c4263f6"/>
**무엇을 만들지보다, 누구의 어떤 문제를 해결할지 먼저 정한다.**
| 구분 | 질문 | 다이어리 설명 예시 |
| --- | --- | --- |
| 목표 | 사용자에게 어떤 변화가 생겨야 하나? | 예상과 실제의 차이를 확인하고 다음 계획을 고친다. |
| 요구사항 | 시스템은 무엇을 보장해야 하나? | 집계 숫자에서 근거 기록으로 이동할 수 있어야 한다. |
| 인수 기준 | 무엇을 보면 통과인가? | 완료 수를 누르면 그 숫자에 포함된 완료 할 일이 보인다. |
| 구현 선택 | 그 결과를 어떻게 만들 것인가? | API·쿼리·화면 구조를 설계한다. 확정 기술 제약은 유지한다. |
## 시작할 때 정할 것
- 사용자·문제·실제 환경·기간·예산·공개 범위.
- 포함할 것과 제외할 것, 이미 확정된 결정.
- 성공을 관찰할 방법과 좋은 명세의 예시.
근거 없는 목표 수치나 사용자 판단은 만들지 않는다. 결과를 바꾸는 빈칸부터 질문하고 **원문 / 사용자 확정 / AI 제안 / 미확정**을 구분한다.
## 조건 하나의 최소 구조
**ID → 출처·상위 목표 → 사전 상태·사건 → 보장할 결과 → 통과·실패 → 증거 → 상태**
원문 ID와 의미를 유지하고, 제안을 승인 없이 필수 조건으로 바꾸지 않는다. 조건이 많아지는 것만으로 정교해지지는 않는다.
