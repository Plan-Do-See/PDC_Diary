# 02 · NASA 요구사항 품질 기준

<mention-page url="https://app.notion.com/p/3d60def9f62681c2bca2cf1e7c4263f6"/>
**NASA는 기관 이름이다. 여기서는 Systems Engineering Handbook의 요구사항 작성·검토 지침을 뜻한다.**
| 품질 기준 | 검토 질문 |
| --- | --- |
| 명확성 | ‘빠르게·적절하게’처럼 해석이 갈리는 표현은 없는가? |
| 단일 의무 | 한 조건에 독립적으로 실패할 여러 의무가 섞이지 않았는가? |
| 필요성·추적성 | 어느 사용자 요구나 상위 목표에서 나온 조건인가? |
| 실현 가능성 | 주어진 환경·기간·비용에서 달성할 수 있는가? |
| 검증 가능성 | 실제 결과로 통과와 실패를 구분할 수 있는가? |
| 전체의 일관성·완전성 | 조건끼리 충돌하거나 필요한 경우가 빠지지 않았는가? |
이는 NASA 지침을 학습용으로 묶어 요약한 것이다. 지침의 모든 항목을 옮긴 표는 아니다.
## 다이어리에 적용하면
**모호한 표현:** “완료를 안정적으로 처리한다.”
**명확한 결과:** “같은 할 일의 같은 완료 주기에서 최초 완료 요청이 겹쳐도 완료 사건은 1건만 남아야 한다.”
집계가 1만 증가하는 의무는 별도 조건으로 검사한다. 원래 T06-C21·C22와 기존 완료 주기를 설명한 예시이며 새 조건이나 실행한 검사 결과가 아니다.
## 한계
좋은 문장인지 검토하는 데 도움이 되지만, 사용자가 원하는 목표가 맞는지와 실제 구현의 성공까지 자동으로 보장하지 않는다.
