## 적용 기준과 구현

RULES.md 전체와 원문44개, 앱 사용 경험 지침, 현재 pds-design, 웹 AGENTS·서버 API/DB 계약, 설치된 Next16.3.4의 Linking and Navigating·Server and Client Components를 확인했다. 계획/할 일 계층, 서버 저장·권한·집계·시간 단위·순서 버전 계약과 공개 안내를 유지한다.

첫 방문은 요청자별 SSR/no-store로 렌더링한다. 이후 세 목록 탭은 공통 레이아웃 안에 유지하고 선택한 본문만 표시한다. Plan 카드 펼침·보기 방식·인라인 입력·상세 선택, Do 조건/미제출 검색, See 근거 선택/작성 입력, 각 탭 주소·스크롤을 보존한다. 숨은 탭은 hidden/inert로 조작 대상에서 제외한다. 주소와 뒤로/앞으로는 Native History API와 Next pathname/search 동기화를 사용한다.

AI 구현 선택: 같은 공간·현재 브라우저 화면에서 성공한 조회를30초 재사용한다. 타이머로 주기 조회하지 않는다. 첫 방문·조건 변경·오래된 탭 재방문/창 포커스·저장 성공 때 기존 REST API를 읽는다. 저장 성공은 다른 탭을 갱신 대상으로 표시하며, 해당 탭에 돌아오면 다시 읽는다. 요청 중에는 현재 화면을 유지한다. 조회 실패는 입력을 보존하고 재시도 버튼을 표시한다. 같은 탭/조건 요청을 합치고 세대 번호로 늦은 응답을 버린다. 이미 취소한 첫 탭 방문은 응답이 도착해도 주소를 바꾸지 않는다.

SSR에서 전달받은 클라이언트 화면의 타입·키를 유지한 채 새 데이터 props만 전달한다. 공개/개인 저장소를 분리하고 로그아웃·세션 만료에는 개인 탭을 비운다. 업무 데이터나 임시 입력을 localStorage에 저장하지 않는다. HTTP no-store와 서버 DB의 최종 판단은 유지한다. 탭 재사용은 DB 저장 검증을 대신하지 않는다.

접힌 계획은 task-order를 조회하지 않는다. 펼쳐져 현재 보이는 계획만 필요한 순서 스냅샷을 조회한다. DND의 서버 버전·CSRF·멱등 키·미확정 재확인 절차는 유지한다. 동일한 할 일을 Plan과 Do에서 열어도 입력 요소 ID가 중복되지 않도록 인스턴스별 ID를 사용한다.

메뉴의 배치·문구·크기·글꼴·기존 민트/살구/라일락을 유지하며 선택 배경이240ms 동안 이동한다. 이는 세 항목 탐색 메뉴이므로 링크·aria-current 의미를 유지한다. 방향키/Home/End와 동작 줄이기를 지원한다. 기존 계획 펼침/접힘 애니메이션도 유지한다.

## 검사 중 발견한 반례

초기 구현의 router.refresh와 빠른 메뉴 전환 조합에서 문서 탐색으로 돌아가 입력이 지워졌다. 탭의 데이터 갱신을 기존 REST 조회로 분리했다. 이어 첫 SSR 화면을 별도로 로드한 컴포넌트로 교체하면 폼이 재생성됨을 확인하고 원래 화면 참조에 props만 갱신하도록 수정했다. 실패 안내 때 DOM은 유지됐지만 성공 재시도 때 바뀌던 대조를 수정 후 같은 DOM·같은 입력으로 확인했다. 비동기 첫 방문과 뒤로가기 경합, 별도 화면에서의 메뉴 진입도 분리했다.

## 범위·실행·복구

지속 보존 범위는 Plan/Do/See의 세 목록 탭이다. 브라우저 새로고침·새 탭·로그아웃·독립 작성/수정 화면 전체에 임시 입력을 영구 복원하는 기능은 아니다. 별도 화면은 기존 Next 라우터로 이동한다. 외부 변경은 실시간 구독 없이 재방문/포커스와30초 기준으로 확인하므로 즉시 반영을 보장하지 않는다. 첫 미방문 탭은 데이터를 기다리며 현재 본문과 메뉴의 작은 대기 표시를 보여 준다.

이번 무JavaScript 보조 검사에서 계획 제목은 보였지만 전체 비JS 기능을 검증하지는 않았다. 새 배포와 오래된 자산이 섞이는 운영 검증·다른 브라우저 전체·실제 사용자1/5/3·최종 DB 계약·전체 인수는 미완료다. 소셜 보류·Figma/PDF 제외를 유지한다.

실행: 격리 API8081 실행 후 웹 저장소에서 API_INTERNAL_URL/LOCAL_API_PROXY_URL을 해당 주소로 지정하고 npm run build, .next/static 및 public을 standalone에 복사한 다음 PORT=3104로 node .next/standalone/server.js를 실행한다. 같은 PC의 http://127.0.0.1:3104/plans 에서 확인한다. 이번 테스트는 해당 배포용 빌드에서 실행했다.

확인 방법: Plan에서 계획 펼침·할 일 임시 입력 → Do/See 왕복 → 입력·펼침·선택 배경 이동을 확인한다. 연결 실패 때는 기존 입력 옆 재시도 안내가 표시된다.

수정 전 로컬 원본은 설계 저장소 tmp/persistent-tabs-backup 및 후속 단계별 백업에 보존했다. 복구 시 이후 사용자 변경과 대조해 이번 패치만 되돌리고 다시 빌드한다. DB 이관은 없다. 기존 배포 묶음에는 이 변경이 없어 소스/해시/배포 입력을 다시 준비해야 한다. 현재 푸시·운영 배포는 미실행이다.
