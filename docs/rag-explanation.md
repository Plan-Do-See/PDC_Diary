# RAG 동작과 준비물 — 설명 기록

별도 학습 정리: [RAG 학습 문서](learning/rag.md) · [노션 학습 → AI·데이터 → RAG](https://app.notion.com/p/3d40def9f626816ab473d0eb05d73ef1). 2026-09-09 학습 본문·흐름도·HTML 지식그래프를 반영했다. 이전 첨부 실패는 해결됐으며 노션 안에서 탭 전환과 노드 설명 변경을 확인했다. 아래는 이전 채팅 설명 당시의 기록이다.

2026-09-09 · 사용자 요청: RAG의 원리·구성·준비물을 채팅에서 설명. 기존 설계와 도입 상태는 유지하며 검색 제품·서비스를 새로 확정하지 않는다.

- RAG는 검색한 근거를 질문과 함께 모델 입력에 제공하는 방식이다. 일반적인 RAG는 모델 가중치를 다시 학습시키지 않는다.
- 준비: 허용한 저장소 문서/소스를 읽고, 문서 절·함수·API 단위로 나누고, 원문 위치·repo·commit/내용 해시·상태·접근 범위를 기록한다. 의미 검색을 쓸 때는 임베딩을 만들고 검색 인덱스에 저장한다.
- 질문 처리: 질문·대상 도메인·접근 권한으로 범위를 정하고 키워드/의미 검색을 수행한다. 후보를 다시 정렬하거나 주변 원문을 읽은 뒤 필요한 근거와 필수 RULE을 모델에 전달한다. 검색 결과의 본문이 모델에 들어가며 벡터는 유사한 본문을 찾는 용도다.
- 역할: 수집/인덱싱 코드가 자료를 준비하고, 검색기가 후보를 찾고, 연결 프로그램이나 코딩 에이전트가 도구를 호출해 문맥을 구성한다. MCP는 Codex가 이 검색/원문 읽기 도구를 호출하도록 연결하는 수단이다.
- 준비물: 접근 가능한 원본, 허용/제외 정책, 수집·분할 코드, 검색 인덱스, 의미 검색 시 임베딩 모델, 검색과 모델을 잇는 도구/프로그램, 변경·삭제 갱신 처리, 대표 질문과 기대 근거.
- 프로젝트 적용: PDC_Diary의 RULE, Spring/Nextjs 구현·계약, Security/Optimization의 관련 채택 결정·증거를 연결한다. 모든 원본을 매번 통째로 넣지 않으며 필수 조건은 검색 상위 결과 제한으로 생략하지 않는다.
- 운영: 처음에는 개발 PC의 로컬 도구로 시작할 수 있다. 제품 MariaDB는 다이어리 자료를 저장하고, 검색 인덱스는 개발 보조 자료로 분리한다. 로컬 임베딩 또는 외부 API 선택에 따라 자원·비용·전송 범위가 달라진다. 로컬 인덱스여도 클라우드 모델에 전달된 원문은 외부로 전송된다.
- 한계: 검색 누락·오래된 원문·관련성 순위 오류·모델의 잘못된 해석은 남는다. 원본 재확인과 계약/회귀 검사가 필요하다.
