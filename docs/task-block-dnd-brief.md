# 할 일 블록과 드래그 순서 변경

후속 결정: 사용자가 제안을 채택해 구현을 시작했다. 현재 상태는 [구현 기록](task-block-order.md)을 따른다. 아래는 브리핑 당시 기록이다.

## 2026-09-11 · 할 일 블록·DND 작업 브리핑
사용자 요청: 할 일도 독립 블록으로 표시하고 할 일 사이의 드래그 위치 변경에 필요한 작업을 설명한다. 이번은 브리핑이며 구현·배포 지시로 확대하지 않는다. Figma 제외를 유지한다.
확인된 현재 상태: 웹 DiaryWorkbench가 Plan/Do의 할 일 article을 공유한다. 순서 안내와 생성 후 재조회는 마감 정렬을 사용한다. 중앙/Spring 목록 계약은 due/priority/estimate/newest 4정렬이며 확인한 OpenAPI에는 재배치 경로가 없다. 따라서 영구 수동 순서는 웹·서버·DB·계약 확장이 필요하다. 운영 DB 실측 및 서버 구현 전체 재검토는 이번 브리핑에서 하지 않았다.
AI 제안: 낮은 높이의 둥근 독립 블록에 드래그 손잡이·이름·상태·마감·우선순위를 배치한다. Plan에서는 부모 계획 안에 들여쓰기하고, Do에서는 소속 계획을 표시한다. 블록 사이 여백과 얇은 테두리로 구분하고 모바일은 1열을 유지한다. 상세 선택·상태 변경·인라인 추가를 유지하며 손잡이를 끌 때만 이동한다. 이동할 자리 표시, 자동 스크롤, 키보드/위아래 이동 대안, 모바일 스크롤 충돌 방지가 필요하다.
초기 범위 추천(미확정): 같은 계획 안의 할 일 순서만 변경한다. Plan은 사용자 순서 보기, Do는 계획 하나 선택+사용자 순서에서 재배치를 제공한다. 검색/오늘·이번주/상태 등으로 일부만 보일 때와 자동 정렬에서는 재배치를 잠그고 전체 사용자 순서 보기로 안내한다. 다른 계획으로 끌어 소속을 바꾸는 기능은 별도 설계한다.
서버/DB 제안(미확정): 할 일 순서값과 계획별 순서 버전을 추가하고 기존 자료는 현재 마감·우선순위·생성 시각·ID 순으로 초기화한다. 같은 공간·계획의 전체 미삭제 할 일 ID 목록과 기대 순서 버전을 받아 중복/누락/권한을 검증한 뒤 한 트랜잭션으로 저장한다. 중복 요청과 동시에 다른 창에서 추가·삭제·순서 변경한 경우를 처리한다. 순서 버전은 계획 내용의 수정 이력과 분리한다. 새 할 일은 끝에 추가, 복원은 끝으로 배치하는 규칙을 추천한다. 복제·내보내기에도 순서값을 포함하고 실행 기록/완료 집계/예상 시간은 바꾸지 않는다.
웹 연결과 검증: 성공 시 서버 확정 순서를 반영한다. 명확한 저장 실패는 원래 순서로 복구하고, 응답 유실·충돌은 최신 목록을 재조회해 안내한다. 생성/완료 후 재조회가 마감 정렬로 되돌리지 않게 수정한다. 실제 격리 DB에서 새로고침 순서 유지, 동시 변경, 실패 복구, 공개/개인 경계, 생성·삭제·복원·복제·내보내기, 기존 정렬·완료·집계 회귀를 확인한다.
진행 순서 제안: 블록 화면 초안 → 수동 정렬 범위/규칙 확정 → DB/API 계약·서버 구현 → 웹 DND 연결 → 검증·배포. 원문44개와 서버 정렬/동률 공개 조건을 유지한다. 이번에는 소스·DB·현행 계약을 수정하지 않고 제안만 기록한다.
