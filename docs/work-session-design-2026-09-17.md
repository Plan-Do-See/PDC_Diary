# PlanDoSee 작업 시간 세션 설계

용어: `작업탭`은 펼친 할 일 내부의 실행 패널이고, `작업바`는 본문 상단에 쌓이는 전역 작업 상태 줄이다.

기준일: 2026-09-17  
상태: 사용자 확정 UI 구상 · 서버/DB/OpenAPI 구현 전

현재 수정 순서: [프론트 컴포넌트 수정 현재 상태](../../PDC_Diary_Nextjs/docs/redesign/frontend-component-editing-state-2026-09-17.md)에 따라 할 일 컴포넌트를 먼저 조율한다. 작업바 컴포넌트는 그다음 별도 단계이며, 할 일 컴포넌트 작업 중에는 수정하지 않는다.

## 목적

사용자가 PlanDoSee에 계속 머물거나 스톱워치를 직접 끄러 돌아오지 않아도 실제 작업 시간을 계산할 수 있게 한다. 할 일의 예상 시간은 선택 입력으로 두고, 확정된 작업 세션만 별도 실행 기록으로 저장해 통계와 회고의 자료로 사용한다.

작업탭의 `1시간 작업 시작` 행동은 초록 포인트색으로 채워진 재생 아이콘과 문구를 함께 사용한다.

## 사용자 확정

- 직전 전체 이식안과 별도 단독 재구성안은 폐기했다. 현재는 롤백된 전체 16:9 원본 화면을 기준으로 고정하고 그 안의 낮고 간결한 기존 접힌 행은 변경하지 않은 채 할 일 컴포넌트 내부만 수정한다. 할 일 본문은 최대 **3줄**로 접고, 실제 렌더 결과가 3줄을 넘을 때만 중앙 화살표로 전체 본문을 부드럽게 펼치거나 접는다. 3줄 이하이면 화살표가 없다.
- 기존 `현재 시각 기록` 한 번 누르기 방식은 폐기하고, 기본 **1시간 작업**을 시작하는 행동으로 바꾼다.
- 예상 작업시간을 입력하지 않아도 작업을 시작할 수 있다. 기본 1시간은 할 일 예상값이 아니라 세션의 최초 자동 종료 기준이며 예상시간을 자동 입력하거나 수정하지 않는다.
- `1시간 작업 시작`을 누르면 세션 생성과 동시에 해당 할 일 상태를 `진행 중`으로 바꾼다.
- 작업 중에는 현재 업무 화면의 **본문 섹션 최상단**에 닫을 수 없는 얇은 작업 탭을 둔다. 선택한 스프린트에서는 스프린트 이름과 진행률보다 먼저 보인다.
- 작업 탭에는 할 일 이름, 분 단위 진행 시간, 자동 종료 시각, `중단`, `+30분 연장`을 표시한다. 중단·자동 종료 뒤 상단 작업 탭과 펼친 할 일 실행 패널의 같은 행동 영역에서 `시간 수정`, `기록 확인`으로 전환한다. 확인 대기 탭의 초록 보조 문구는 8px이다.
- 여러 작업이 동시에 진행 중이면 작업별 탭을 한 줄씩 세로로 쌓는다. 최상단으로 이동하는 것은 이 축약 탭뿐이며, 펼친 할 일 상세 카드는 해당 할 일의 목록 위치에 남긴다.
- `중단`하거나 1시간이 지나 자동 종료되면 계산된 시간을 바로 확정하지 않고 확인·수정할 수 있게 한다. `기록 확인`을 누르면 성공 피드백 후 해당 탭을 부드럽게 접어 제거한다.
- 모바일에서도 같은 흐름을 유지하되 보조 문구를 줄이고 핵심 시간과 두 행동을 남긴다.

- 계정 또는 공개 작업공간에서 서로 다른 할 일의 작업 세션을 동시에 진행할 수 있다. 같은 할 일의 활성 세션 중복만 막는다.

## AI 추천 · 구현 전 최종 채택 필요

- `+30분 연장`은 현재 자동 종료 시각에 30분을 더하며 횟수 제한은 두지 않는다.
- 브라우저를 닫아도 서버의 `started_at`과 `planned_end_at`으로 활성 상태를 복원한다. 브라우저 타이머 자체를 저장하지 않는다.
- 자동 종료된 세션은 `확인 필요` 상태로 남기고, 사용자가 확인하거나 시간을 고친 뒤에만 최종 `execution_logs`와 통계·회고에 반영한다.
- 확인 전 세션은 내보내기에 `pending` 상태로 포함해 유실은 막되 실제 실행 합계에는 넣지 않는다.
- 서버가 제공하는 현재 시각을 기준으로 분 단위 시간을 계산한다. 클라이언트 시계와 탭 실행 여부를 신뢰하지 않는다.

## 상태 흐름

1. 사용자가 할 일의 `1시간 작업 시작`을 누른다.
2. 서버가 `started_at`, `planned_end_at = started_at + 60분`, 대상 할 일과 소유 공간을 저장한다.
3. 모든 인증 화면은 활성 세션들을 조회해 현재 본문 섹션 최상단의 작업 탭 묶음으로 복원한다.
4. `+30분 연장`은 `planned_end_at`만 늘린다. `중단`은 서버 종료 시각으로 경과 시간을 계산한다.
5. 자동 종료 또는 중단 뒤 세션은 `확인 필요`가 된다.
6. 사용자가 확인하면 불변 시작·종료 시각과 서버 계산 분을 실행 기록으로 만든다. 수정하면 원래 자동 계산값과 수정값을 구분해 보존한다.

## 섹션 최상단 작업 탭 묶음

- 위치: 선택한 스프린트나 전체 할 일 **본문 섹션 안의 최상단**. 섹션 제목·기간·진행률보다 위에 두고, 앱 전역 헤더나 화면을 덮는 `position: fixed` 오버레이로 만들지 않는다. 필요하면 해당 스크롤 영역 안에서만 `sticky`로 유지한다.
- 구성: 활성 세션마다 축약 탭 한 줄을 만들고 세로로 쌓는다. 펼친 할 일 상세 전체를 이 영역으로 옮기지 않는다.
- 높이: 탭 한 줄의 기본 최소 높이는 42px이며 90% 시안에서는 약 37.8px로 보인다. 모바일은 탭마다 최대 두 줄로 재배치한다.
- 왼쪽: 활성 점, `작업 중`, 할 일 제목.
- 가운데: `진행 24분`, `15:40 자동 종료`.
- 오른쪽: 활성 상태는 위험도가 높은 `중단`, 보조 행동 `+30분 연장`; 확인 대기 상태는 `시간 수정`, 강조된 `기록 확인`.
- 상단 확인 대기 작업바의 `기록 확인`은 `기록됨` 버튼 피드백과 `실행 기록 저장됨 / 통계 반영 완료` 성공 상태를 220ms 먼저 보여 준 뒤 320ms 축소·퇴장한다. 할 일 내부 작업탭의 `기록 확인`도 연결된 작업바의 같은 모션을 호출한다.
- 밀도: 내부 간격 8px, 세로 여백 5px, 행동 버튼 기본 높이 28px를 사용한다. 상태점과 제목·시간 크기도 함께 줄여 작업 탭이 본문보다 과하게 무겁지 않게 한다.
- 확인 모션: `기록 확인` 버튼이 `기록됨`으로 바뀌며 짧게 눌린 뒤 탭이 320ms 동안 위로 이동하면서 높이와 불투명도가 0으로 줄어든다. 동작 줄이기 환경에서는 즉시 제거한다.
- 닫기 버튼은 두지 않는다. 활성 작업이 있으면 항상 보이므로 사용자가 무엇을 기록 중인지 잊지 않는다.
- 현재 진행 중인 작업 탭만 쌓고 과거 실행 기록은 쌓지 않는다. 과거 기록은 할 일 상세에서 본다.

## 할 일 확장 블록

- 3줄을 넘는 본문은 3줄 미리보기 → 중앙 화살표 → 전체 본문 순서다. 3줄 이하인 본문은 화살표 없이 본문 전체를 그대로 표시한다.
- 해시태그형 핵심 정보는 본문 열 하단에 마감·예상·실제 순서로 붙인다. 예상시간이 없으면 `#예상` 태그를 억지로 만들지 않고 생략하며, 편집 화면에서는 `예상 미입력`으로 명확히 구분한다.
- 오른쪽 작업 카드의 기본 상태는 `작업 시간 / 1시간 / 기본 블록 / 1시간 작업 시작`이다.
- 활성 상태는 `진행중 / 00:24:00 / 15:40 종료`로 바뀌고 부드러운 초록 계열 배경을 사용한다. 경과 시간은 `00:00:00` 형식으로 1초마다 갱신한다.
- 활성 패널 하단에는 위험색 `중단`과 녹색 `30분 연장`을 나란히 둔다. 본문 섹션 최상단 작업 탭에도 기존 축약 행동을 유지한다.
- 시작 전후 상세 패널의 외곽 크기, 시간 글자 크기, 행동 영역 높이를 유지한다. 새 활성 작업 탭은 340ms 동안 높이와 불투명도가 자연스럽게 증가하고, 새 상세 패널만 320ms 상태 전환을 재생한다. 기존 활성 작업 탭은 다시 등장하는 모션을 재생하지 않는다.
- `중단` 문구는 같은 행동 줄보다 조금 더 굵은 850을 사용한다.
- 실행 기록 전체 편집은 기존 합의대로 전체 일정의 할 일 상세에서 연다.

## 데이터·동시성 계약 초안

최종 DB와 OpenAPI에는 구현 전에 아래 계약을 확정해야 한다.

- `work_sessions`: `workspace_id`, `id`, `task_id`, `started_at`, `planned_end_at`, `stopped_at`, `status`, `revision`, `created_at`, `updated_at`.
- 상태: `active`, `stopped_pending`, `auto_ended_pending`, `confirmed`, `discarded`.
- 같은 작업공간에 서로 다른 할 일의 `active` 세션 여러 건을 허용하되, 같은 할 일의 `active` 세션은 최대 한 건이다. 시작·중단·연장·확인은 요청 키와 원자적 상태 전환으로 중복을 막는다.
- 실제 분은 서버가 확인 시각과 시작 시각의 차이로 계산한다. 확정된 결과는 기존 `execution_logs`에 연결한다.
- 접근 경계, soft delete, 내보내기, 같은 응답 근거, UTC 저장·서울 표시 규칙은 기존 계약을 그대로 적용한다.

## 통계와 회고

- 통계의 실제 시간은 **확정된 실행 기록만** 합산한다.
- 예상 대비 비교는 예상시간이 있는 할 일만 대상으로 하고, 실제 시간도 그 할 일에 연결된 확정 실행 기록만 합산한다. 예상 입력 수와 미입력 수를 함께 보여 비교 범위를 밝힌다.
- 예상시간이 없는 할 일의 확정 실행 기록은 전체 실제 기록 합계와 목록에 계속 포함한다. 비교용 실제 합계와 전체 실제 합계를 같은 값처럼 취급하지 않는다.
- 자동 종료 후 미확인 세션은 상단 알림과 할 일 상세에 `확인 필요`로 표시한다.
- 회고에서는 예상 시간 대비 확정 실제 시간, 완료·지연·막힘을 함께 본다.
- 실제 시간 숫자를 누르면 해당 할 일과 확정 실행 기록으로 이동한다.

## 현재 범위와 남은 일

- 롤백: 전체 16:9 시안에 이식했던 새 할 일 컴포넌트와 이후의 별도 단독 재구성은 접힌 상태가 원본과 다르다는 사용자 지적으로 폐기했다. 전체 화면의 기존 낮은 할 일 행을 실제 코드 그대로 복원했고, 이제 같은 원본 화면 안에서만 컴포넌트 내부를 수정한다. 브라우저에서 접힘·펼침 모두 머리 행 높이 43.1875px(90% 화면 배율), 원본 머리 행 8개·대체 머리 행 0개, 긴 본문 화살표 표시, 3줄 이하 본문 화살표 숨김, 상세 전환 150~260ms를 확인했다. 제품 코드 결합과 사용자 확정은 아직이다.
- 미완료: Next.js 제품 구현, Spring API, MariaDB 마이그레이션, OpenAPI·최종 스키마 계약, 여러 기기 동시성, 자동 종료 작업, 통계 반영, 320px 제품 검증, 배포.
- 이 문서와 시안의 예시 시간은 합성 화면 자료이며 사용자의 실제 실행 기록이 아니다.
- 시안 브라우저에서는 예정 할 일의 작업 시작 후 상태 자동 전환, 활성 패널 전환, 시계 `00:00:02 → 00:00:03`, 중단·연장 버튼 색 구분을 확인했다. 서버 시각 복원과 실제 자동 종료는 아직 검증하지 않았다.
- 90% 브라우저 렌더에서 시작 전후 상세 패널 `180×95.59375px`, 시간 글자 `15px/18px`, 행동 영역 약 `158.21875×32.390625px`로 일치함을 확인했다.
